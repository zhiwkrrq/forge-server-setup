# Forge开服教程：从 Java 版本对不上到整合包稳定跑，新手也能自己把模组服搭起来

装 Forge 服务端这件事，难的不是 Forge 本身。

真正容易卡住新手的就三件事：Java 版本和游戏版本对不上、内存给少了导致玩家一进服就卡、以及服务器到底放哪儿。这三点解决完，剩下都是照着敲命令。

下面按实际操作顺序走一遍。

## 一、动手前先定版本，Java 装错一定起不来

Forge 是 Minecraft Java 版的模组加载器，从 2011 年用到现在，市面上大多数整合包（RLCraft、All The Mods、FTB 系列）都跑在它上面。它本身对 Java 版本很敏感，装错了服务端会直接退出，报一句 `Unsupported class version` 就没了，什么都不解释。

对照关系如下：

| Minecraft 版本 | 需要的 Java 版本 |
| --- | --- |
| 1.16 及以下 | Java 8 |
| 1.17 ～ 1.20.4 | Java 17 |
| 1.20.5 及以上 | Java 21 |

选版本的正确顺序是倒着来的：先确定你要玩的整合包支持哪个游戏版本，再倒推 Forge 版本，最后确定 Java。很多经典整合包只支持 1.12.2 或 1.16.5，这时候就得老老实实装 Java 8，用最新版 Java 是起不来的。

高版本确实性能更好、内容更多，代价是 1.18 以上的资源消耗大约是 1.16 的两倍、1.12.2 的三倍。老机器开高版本模组服会很难受。

## 二、Forge 服务端安装：两条路，选一条

### 路径 A：有 Linux 服务器，手动装

1. 去 Forge 官网下载对应版本的 Installer，文件名类似 `forge-1.20.1-47.x.x-installer.jar`。
2. 新建一个**空文件夹**（安装器要求目录为空），把 jar 放进去。
3. 命令行执行 `java -jar forge-1.20.1-47.x.x-installer.jar --installServer`。注意是 `--installServer`，服务器上没有图形界面，双击那种 GUI 安装方式在这里用不了。
4. 安装完成会生成 `run.sh`（Windows 上是 `run.bat`）、`user_jvm_args.txt` 和 `libraries/` 目录。
5. 第一次启动会在根目录生成 `eula.txt`，把里面唯一一个 `false` 改成 `true`，保存。
6. 再执行 `./run.sh`，看到日志里出现 `Done (xx.xxxs)! For help, type "help"` 就算起来了。

Windows 上有个高频报错：提示找不到主类 `@user_jvm_args.txt`。这通常不是文件坏了，而是 `run.bat` 里调用的 `java` 没有指向你实际安装的 Java 路径，把脚本里的 `java` 替换成完整的 `java.exe` 路径即可。

如果你不想碰命令行，直接租带面板的游戏服是更省事的做法。面板会替你处理 Java 环境和服务端下载，你只要选好游戏版本和对应的模组端类型，剩下的在网页上点。

## 三、开服后真正影响体验的几个参数

装完能启动只是及格线，服务器顺不顺是这几个参数决定的。

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| `server-port` | 25565 | Java 版默认端口，记得在控制台/安全组放通 TCP |
| `max-tick-time` | 180000 | 模组服必须放宽，整合包加载慢，默认值容易误判为卡死 |
| `allow-flight` | true | 模组服基本都要开，飞行坐骑和道具会被原版规则踢 |
| `spawn-protection` | 0 | 不然新人进服没法在出生点放方块 |
| `view-distance` | 原版 8～10，模组服 6～8 | 视距每加 1 档，CPU 和内存压力都会明显上升 |
| `simulation-distance` | 比视距低 2～4 | 生物和方块刻的模拟范围，对性能影响比视距更直接 |

内存分配写在 `user_jvm_args.txt` 里，格式是 `-Xmx12G -Xms12G`，注意把原来带 `#` 的示例行删掉或注释干净，否则不生效。

给多少内存，按这个粗略估算：

- 原版 2～5 人：4GB 够用
- 原版加插件、5～15 人：4 核 8GB
- 模组服（50 个 mod 左右）：8GB 起步
- 大型整合包（200 mod 以上）：12GB 以上，视距还得压下来

有一个反直觉但很重要的点：**MC 的主逻辑跑在单线程里，单核主频比核心数重要得多。**同样是四核，主频 3.4GHz 的老 E5 和睿频 5.7GHz 的 Ryzen 7950X，玩家人数一多差距会非常明显。所以选机器时先看单核性能，再看核心数。

另外，给 Java 的内存别顶满物理内存。建议设成总内存的 60%～70%，剩下留给系统和面板，设满了反而会因为系统无内存可用而崩溃。

## 七、启动后的常见报错，按这张表查

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| `Unsupported class version` | Java 版本低于游戏版本要求 | 按第一节的对照表换成对应 Java |
| 服务端启动后立刻退出，日志很短 | `eula.txt` 还是 false | 改成 true 保存后重启 |
| 找不到主类 `@user_jvm_args.txt` | 启动脚本里的 java 路径不对 | 脚本里改成 java.exe 的完整路径 |
| 整合包加载到一半判定卡死 | `max-tick-time` 没放宽 | 设为 180000 |
| mod 不加载 | 文件放错目录或版本不匹配 | 确认放在 `mods/` 且与 Forge 版本兼容 |
| 加完 mod 就崩 | 缺少前置依赖或 mod 冲突 | 清空 mods 后分批加回，每批 5 个，定位到具体文件 |
| 玩家进不来但自己本地能连 | 没放通 25565/TCP，或用了 NAT 没做端口映射 | 放通端口，NAT 机型检查映射条数 |
| 人一多就卡，控制台刷 `Can't keep up` | 单核性能或内存不够 | 降视距、加内存，或换高主频机型 |

排查顺序建议从 Java 版本开始。新手遇到的启动失败，八成都在这一步。

## 八、什么情况下该升级，什么情况下不值得

判断标准其实很具体：

- 稳定在线 5 人以内、原版或轻插件，2 核 4G 足够。往上升配置不会带来任何肉眼可见的提升。
- 玩 50 个 mod 左右的中型模组服，4 核 8G 是合理起点，重点确认内存有富余。
- 200 mod 以上的大型整合包，从 6 核 12G 起步，并且必须选高主频 CPU。这时候省 CPU 的钱等于白买内存。
